## Что должно заработать

Полная статичная (без анимаций — их добавит тикет 03) структура одностраничного лендинга Corex-Trade: восемь секций из спецификации, наполненные реальным (не заглушечным по смыслу) русским текстом, кроме мест, явно помеченных как плейсхолдер (кейсы, контакты, Hero-визуал). Каждая секция визуально не похожа на соседние по композиции. Калькулятор и контактная форма работают на чистом JS без бэкенда. Всё адаптивно (мобильный/планшет/десктоп). Использует только токены из `css/tokens.css` (тикет 01) — ничего не хардкодит в обход них.

Восемь обязательных секций:
1. **Hero** — что делает компания, ценностное предложение, основной CTA («рассчитать доставку»→якорь на калькулятор) и вторичный CTA («как это работает»→якорь на секцию 2). Визуал-заглушка сцены (SVG/CSS) под будущую замену на видео — контейнер и разметку подготовь так, чтобы `<video>`/картинку можно было подставить одной заменой без перестройки вёрстки. В разметке предусмотри 6 подписей этапов в точности **«фабрика → производство → документы → сертификация → логистика → Россия»** (не путать с 7-узловым маршрутом секции 2 — это разные последовательности, см. `spec.md`) — каждая как отдельный элемент с `data-animate`, скрытый по умолчанию (тикет 03 их покажет по прогрессу скролла). Расставь остальные `data-animate` атрибуты по контракту из `interfaces.md`, но саму анимацию не пиши.
2. **Как работает импорт** — маршрут Фабрика → переговоры → проверка → сертификация → документы → логистика → Россия, 7 узлов, минимум текста (2–4 слова на узел + иконка).
3. **Что мы берём на себя** — поиск фабрики, переговоры, проверка, сертификация, документы, таможня, логистика, доставка — как схема передачи процесса клиент→компания.
4. **Калькулятор** — форма с полями (предложи сам, не перегружая — например: тип груза/категория, вес, объём или габариты, способ доставки авто/жд/море/авиа, город назначения). `id="calculator-form"`, вывод в `#calculator-result`. `js/calculator.js`: валидация обязательных полей с инлайн-сообщениями об ошибке, расчёт по прозрачной формуле-плейсхолдеру с комментарием `// TODO: реальные тарифы`, результат — диапазон с подписью «предварительно, точную стоимость подтвердим после проверки груза», кнопка «отправить как заявку», которая передаёт введённые параметры в форму секции 8 (например через `sessionStorage` или прямое проставление значений полей + скролл к форме).
5. **Кейсы** — 3–4 карточки-заглушки (тип груза, SVG/CSS-плейсхолдер вместо фото, краткая задача, что сделано, результат) — весь текст обобщённый, без конкретных цифр/имён клиентов, с классом `is-placeholder` и видимой пометкой «пример».
6. **Категории / что привозим** — 6–8 категорий (робототехника, платы и комплектующие, промышленное оборудование, дозаторы, электроника, производственные компоненты, другое) с иконками.
7. **Почему с нами** — 3–4 коротких тезиса с иконкой/визуальной метафорой каждый, без длинных абзацев.
8. **Финальный CTA / контакты** — сильный визуально обособленный экран, форма `id="contact-form"` (имя, контакт, комментарий), плейсхолдер-контакты (телефон/почта/мессенджер, явно как заглушка типа «+7 (000) 000-00-00 — впишите реальный»). `js/contact-form.js`: клиентская валидация, на submit — `preventDefault`, показать состояние «заявка отправлена», `console.log` данных с комментарием `// TODO: подключить реальный endpoint`.

Название компании везде — **Corex-Trade** (не ChinaLogist, это только в референсе). Текст обслуживает и крупный завод, и мелкого продавца на маркетплейсе одной и той же историей, без разделения на сегменты.
