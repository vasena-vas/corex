**Волна:** 3
**Status:** ready (после 02)

## Что должно заработать

Весь анимационный слой сайта, подключаемый через GSAP 3 + ScrollTrigger (CDN), читающий разметку и `data-animate` атрибуты, расставленные тикетом 02 (см. `interfaces.md` → «Что построено»). Ничего в HTML-структуре/контенте не меняется — только читается и оживляется.

**Hero — главная и самая сложная сцена, заметно сложнее любой другой анимации на странице** (R28.3): больше слоёв (сцена + pin + scrub + последовательные подписи), больше скролл-дистанции, больше отдельных шагов, чем у любой другой секции — это осознанная кульминация, а не одна из равных. Секция запинена (`pin: true`) на время скролл-дистанции, равной высоте вьюпорта в 2–4 раза. По мере скролла: транспортно-логистическая сцена (SVG/CSS-заглушка из тикета 02) проигрывается через `scrub` — прогресс анимации жёстко привязан к прогрессу скролла, не к времени. По ходу сцены последовательно появляются ровно 6 плавающих подписей этапов **в этом порядке**: фабрика → производство → документы → сертификация → логистика → Россия — каждая появляется и уходит в свой отрезок скролл-прогресса, не наложением всех сразу. (Не путать с 7-узловым маршрутом секции 2 — другая последовательность, см. `spec.md`.)

**Остальные секции — минимум 5 разных типов поведения** из списка брифа, распределённых так, чтобы поддерживать смысл каждого блока, не быть декором ради декора:
- Секция 2 (маршрут) — узлы появляются последовательно вдоль пути по мере скролла (stagger/timeline по прогрессу), либо линия маршрута «дорисовывается» скроллом.
- Секция 3 (что берём на себя) — элементы появляются с эффектом «передачи» (например смещение к центру/схлопывание к иконке компании), раскрытие карточек.
- Секция 5 (кейсы) или секция 6 (категории) — горизонтальное движение объектов и/или параллакс.
- Переходы между секциями — плавные (изменение масштаба/затухание фона), не резкий обрыв.
- Обычный fade/slide-in при входе в вьюпорт — там, где сцене не нужно ничего сложнее.

**Обязательно:**
- `prefers-reduced-motion: reduce` — отключить scrub/pin-эффекты и purely decorative motion; контент должен быть виден в конечном состоянии сразу, без анимации.
- На мобильной ширине pinned-сцена Hero не должна ломать вёрстку/быть нечитаемой — упрощённая ветка (короче дистанция скролла или без pin, с обычным reveal).
- Все таймлайны/ScrollTrigger-инстансы — в `js/animations.js`, ничего не пишется инлайн в HTML кроме `data-animate` (которые уже расставлены).

## Из брифа, дословно

> «Главный визуальный прием — динамическая транспортно-логистическая сцена, раскрывающаяся через Scroll Trigger-анимацию.»
> «При скроллинге видео должно проигрываться в зависимости от положения пользователя на странице.»
> «Анимация должна ощущаться как часть интерфейса, а не как декоративный эффект.»
> «Hero-анимация должна быть самой впечатляющей и сложной. В остальных секциях анимации должны поддерживать смысл блока»
> «появление элементов при скролле; параллакс; горизонтальное движение отдельных объектов; изменение масштаба; раскрытие карточек; движение по маршруту; последовательное появление этапов; закрепленные визуальные сцены; переходы между секциями»
> «Анимации должны быть плавными и функциональными, а не декоративными ради декоративности.»

## Критерии приёмки

- [ ] GSAP + ScrollTrigger подключены (CDN), инициализация в `js/animations.js`, файл ничего не знает про `calculator.js`/`contact-form.js`
- [ ] Hero: секция пинится, сцена анимируется через scrub, ровно 6 этапов («фабрика → производство → документы → сертификация → логистика → Россия») появляются последовательно, не одновременно
- [ ] Hero-анимация субъективно и объективно (число слоёв/шагов) сложнее любой другой анимации на странице
- [ ] Минимум 5 явно различных типов ScrollTrigger-поведения реализовано и каждое привязано к секции, где оно осмысленно (не одна и та же fade-in анимация на всех 8 секциях)
- [ ] `prefers-reduced-motion: reduce` — проверено вручную (эмуляция в devtools): pin/scrub отключены, контент читаем без анимации
- [ ] Мобильная ширина (~375px) — hero и остальные анимации не ломают вёрстку, скролл не залипает намертво
- [ ] Анимации не блокируют доступ к контенту клавиатурой/скринридером (элементы не остаются `opacity:0`/`visibility:hidden` после проигрывания, если JS отключён или ScrollTrigger не инициализировался — контент виден по умолчанию, анимация — прогрессивное улучшение)
- [ ] Полный ручной прогон сверху донизу в браузере: ни один переход между секциями не выглядит резким обрывом
